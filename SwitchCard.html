Port roles & VLAN tips

Names come from your recipe. Access: portfast + bpduguard. Trunk: mode trunk only. {{VLANS}} builds Layer-2 vlan lines. Management L3 is the SVI (often Vlan100) or a Loopback, chosen in the recipe editor; a loopback design also needs a Routed uplink. Bulk-apply VLAN to checked Access/Trunk. IP/mask columns appear only for Routed ports.

Updates checked Access and Trunk ports only. Unused and Routed are skipped.

This recipe does not use a port section.

Recipe editor

              
            

            

              
            

            

              

                
              

              

                
              

            

            

              Placeholders: {{HOSTNAME}}, {{MGMT_IP}}, {{MGMT_MASK}}, {{MGMT_VLAN}}, {{GATEWAY}},
                {{SITE}}, {{VLANS}}, {{PORTS}}, {{MGMT_INTERFACE}}, {{MGMT_SOURCES}}. Add fields with
                {{UPPER_SNAKE}}. Apply, then Back to card builder to see new fields.
            

            

              
              
              Write interface {{MGMT_INTERFACE}} in the template and use the same
                placeholder wherever a source interface is needed. A loopback design also needs
                ip routing, a Routed uplink or SVI towards the gateway, and
                ip route 0.0.0.0 0.0.0.0 {{GATEWAY}} instead of
                ip default-gateway.
            

            

              Edit management source commands ({{MGMT_SOURCES}})
              

                One command per line. {{MGMT_INTERFACE}} follows the choice above, so
                  changing the management VLAN or loopback moves the NTP, RADIUS, logging and SSH
                  sources together. Add ip tacacs source-interface or
                  snmp-server trap-source lines if your standard uses them.
              

              
            

            

              
              

                SKU preset notes
                

                  Choosing a SKU fills Available interface names with typical CLI
                    names for that PID (starting point only). You still must click
                    Apply recipe changes to keep them on the recipe. Always confirm
                    with show ip interface brief on the real device (combo/SFP vs copper
                    still share GigabitEthernet names on IE3x00/IE3100). AppGigabitEthernet is omitted
                    from presets (not used in recipes). On IE3x00 modular (IE3400 + IEM), expansion
                    ports are Gi2/x (module 2), not a continued Gi1/x sequence —
                    confirm on device.
                

              

            

            

              

                
              

              
            

            

              
            

            

              Fill from show ip interface brief
              

                Paste show ip interface brief or show interfaces status
                  output from the switch. Physical Ethernet ports are kept in device order; Vlan,
                  Loopback, Port-channel, Tunnel, AppGigabitEthernet and the out-of-band
                  GigabitEthernet0/0 port are skipped. Then click Apply recipe
                  changes.
              

              
              

                
              

            

            

              Edit port role commands
              

                Role placeholders: {{INTERFACE}}, {{VLAN}} (Access), {{DESCRIPTION}},
                  {{PORT_IP}}, {{PORT_MASK}}. Trunk is mode trunk only. Routed uses no switchport +
                  per-port IP/mask.
              

              
            

            
            

              Advanced output options (opt-in, not device-tested)
              
              
              

                Both are off by default. Try them on a spare switch first — see
                  docs/EEM-CONTRACT.md. default interface wipes any existing port
                  config (including on the uplink you are connected through).
              

            

            

              
            

            

              Apply, then Save project / team package to keep changes across
                folders. Autosave holds an unapplied draft in this browser only (not firmware).
